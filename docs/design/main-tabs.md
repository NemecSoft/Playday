# 顶层选项卡（主页 / 游戏资料 / 工具 / 每个游戏一个标签）

> 2026-09-15 改版。改之前：主界面是"**路由制**" —— 主页是 `/`，点「详情」跳 `/game/:id`，
> 详情页**整块替换**掉主页（主页连侧栏一起被卸载）。用户的原话是
> *"现在点击详情，就把主页挡住了"*。
> 改之后：详情是**另一个选项卡**，主页只是"切走"、从不卸载。

## 1. 结构

```
[☰] [主页] [游戏资料] [工具] │ [艾尔登法环 ×] [30XX ×] … …… [主题] [⛶ ─ □ ×]
      └──── 固定组 ────┘  ↑   └── 游戏组：可压缩、可横向滚动 ──┘
                    分隔线
```

| 类型 | 数量 | 可关 | 说明 |
| --- | --- | --- | --- |
| 固定标签 | 恒为 3 个 | **否** | 主页 / 游戏资料 / 工具。它们是入口 —— 允许关掉就没地方点回来了 |
| 游戏标签 | 动态 | 是 | id 形如 `game:<gameId>`，一个游戏一个，**已经开着就只切换**（不重复开） |

**两组是两个独立的容器**（`topbar-fixed-tabs` / `topbar-game-tabs`，中间一条分隔线）。为什么必须分开：
共用一个滚动容器时，游戏标签一多会把固定三个一起滚出视野 —— 而它们不可关，滚没了就**没地方点回主页**。

宽度不够时的顺序是「**先压缩每个游戏标签 → 压到下限（78px）才开始横向滚动**」，固定组与徽标区都不参与压缩。
所以开满 10 个标签也**看得见大部分**（文字出省略号、hover 出全名），而不是"只滚不压"那样一次只露三四个。

> ⚠️ 顶栏右侧**不再有版本徽标**。它原是绝对居中、不占位置的，标签一多就从它底下穿过去（现场反馈
> "会产生遮挡，乱"）；2026-09-15 整块挪到了右下角状态栏（背景音乐右边）。见
> [user-level-detection.md](./user-level-detection.md) 的 UX 表与 `src/components/TierBadge.tsx`。

## 2. 规则（全在 `src/utils/tabs.ts`，纯函数 + 单测）

| 行为 | 规则 | 为什么这么定 |
| --- | --- | --- |
| 打开 | 已经开着 → 只切换；没开 → 追加到末尾并激活 | 重复开会让同一个游戏出现两个标签、还各起一个 iframe |
| 激活 | 记进**访问历史**（`history` + `historyIndex`） | Alt+←/→ 要靠它 |
| 激活同一个 | **不新增历史项** | 否则反复点同一个标签会把历史撑满，Alt+← 退不回真正的上一个 |
| 从历史中间切走 | 截断后面的分支（浏览器行为） | 与浏览器一致，避免 Alt+→ 回到已经"过期"的分支 |
| 关闭 | 固定标签**不可关**；关掉当前标签 → 退到历史里的**前一格** | 浏览器行为；"随便挑一个"会让用户莫名被丢到别的标签 |
| 上限 | 游戏标签最多 `MAX_GAME_TABS = 10`，超了挤掉**最久没访问**的那个（当前激活的不动） | 每个标签是一个**常驻 iframe**，不设上限会一直占内存 |
| 一键关多个 | 标签右键 → 关闭此标签 / **关闭其它游戏标签** / **关闭全部游戏标签**（后两项 = `closeGameTabs(state, keepId?)`） | 开满 10 个之后一个个点 ✕ 太烦；这是上限的配套出口。固定三个不受影响 |
| 激活标签滚进视野 | 激活的标签自动 `scrollIntoView` 到可见范围 | 滚动条是隐形的，否则从主页点开的标签落在滚动区外 —— 看着像"点了没反应" |
| Alt+← / Alt+→ | 按访问顺序回上一个 / 下一个选项卡 | 改版前这两个键走"路由前进/后退"（主页 ↔ 详情），换选项卡后等价行为就是它 |

不变式：**`history` 里的每个 id 一定也在 `tabs` 里**（关闭时两边一起删）——
`closeTab` 靠它保证"退回的那一格一定还开着"。

## 3. 挂载策略：首次进入才挂载、之后常驻

| 决定 | 理由 |
| --- | --- |
| **常驻**（切走不卸载） | 主页要保住滚动位置、游戏资料要保住搜索词、游戏详情要保住 iframe（卸载 = 那一页重新加载）。需求明确"再点回来内容还在" |
| **首次进入才挂载** | 游戏资料那页 376 KB + 1280 张懒加载封面，每个详情页各自要起一次本地服务器 —— 开屏全挂上会明显拖慢启动 |
| 隐藏用 `invisible`（visibility:hidden）+ `absolute inset-0` | ⚠️ **不是 `display:none`**：主页的网格是**虚拟列表**（按容器尺寸测量行高），`display:none` 会让它量到 0，切回来有行高错位的风险。`visibility:hidden` 保留布局盒，测量与滚动位置都稳。配合 `absolute`，同一时刻只有一个标签占版面（否则两个 `flex-1` 会把高度劈成两半） |

**代价**：选项卡切换**没有淡入淡出动画**了（改版前 `MainContent` 用 `AnimatePresence` 做）。
要动画就得让非当前标签脱离 `display` 层面去做过渡，会跟上面那条虚拟列表的约束打架 —— 不值得。

## 4. 与路由的关系

- `/` → `AppBody`（侧栏 + 选项卡内容）。**详情不再是路由**。
- `*` → 兜底回主页：老的 `#/game/xxx` 深链接不会白屏。
- 侧栏只在「主页」标签下显示（标签筛选与游戏标签无关）。

## 6. 顺带的后果

- **`VideosView` 现在没有入口了**：2026-09-14 就把"视频"页签从顶栏拿掉了（视频区块注入在详情页里），
  当时"视图与渲染分支都保留"；这次标签改成动态列表后，标签 id 里已经没有 `videos` 这一项，
  所以渲染分支删掉了。文件保留（未引用）—— 要恢复就是加一个固定标签的事。
- 「游戏资料」标签（静态站总目录页）与游戏标签**互不影响**，见 [game-details.md](./game-details.md)。
