# 存档管理（备份-恢复）设计文档

> 状态：设计定稿 v1.0（2026-08-15 决策确认）
> 本文档描述 Playday 客户端"游戏存档备份-恢复"功能的设计，包含数据模型、备份/恢复流程、
> NSIS 打包方案、多存储接口、用户登录联动与 UI 设计。

## 已确认的决策

| 维度 | 决策 |
| --- | --- |
| 备份产物格式 | **仅 NSIS 自解压 exe**（双击即恢复） |
| 存档路径配置方 | **管理端配置 savePaths**（下发到客户端，集中管控） |
| 触发时机 | **游戏退出时自动备份**到用户指定位置（另有手动备份） |
| 用户绑定 | **宽松**：备份不强制绑定用户，游客也能恢复任意备份 |

---

## 一、需求背景

- **场景**：无盘网吧 / 网吧 / 多台机器切换场景，用户希望把游戏存档带走、换机后恢复。
- **痛点**：存档往往分散在**多个路径**（有的在安装目录、有的在 `C:\Users\...\AppData`、有的在
  `Documents\My Games` 等），且不同游戏路径不同。
- **旧方案缺陷**：WinRAR 自解压 exe 只能处理"单一起点"，多路径处理繁琐，且生成的自解压包
  用户难以理解和管理。

### 目标

1. 支持一个游戏**最多 3 个存档路径**（文件或目录）的打包。
2. 备份产物可**移动到任意位置**（U 盘 / 网盘 / 本地目录）。
3. 恢复时能把多个路径**放回正确位置**。
4. 备份-恢复**与用户登录联动**（每个账号有自己的存档）。
5. 预留**多种存储接口**（本地 / U 盘 / 网盘 / 未来云端）。

## 二、数据模型

### 2.1 Game 新增字段：存档路径列表

```ts
// 每个游戏的存档路径配置（最多 3 个）。
savePaths: SavePath[];

interface SavePath {
  id: string;       // 唯一 id（用于管理端编辑时增删）
  path: string;     // 存档路径，含通配符，支持 {游戏库名} 占位符。
                    // 例："C:\Users\...\Scrap Mechanic\*.*"、"X:\YunGame\...\settings\*.save"
  type: "file" | "dir";  // 是文件还是目录（有通配符时按通配符匹配文件）
  note?: string;    // 备注（如"配置文件"、"存档目录"），可选
}
```

### 路径格式（含通配符）

- 路径**原样保留通配符**（`*.*`、`*.save` 等），因为 NSIS 原生支持通配符匹配。
- 备份时：
  - 路径无通配符 → 直接收集该文件/目录全部内容。
  - 路径含通配符 → 只收集匹配到的文件/目录（如 `*.save` 只备份该扩展名的文件）。
  - 支持 `{游戏库名}` 占位符（先 resolvePath 展开）。
- 存到数据库 `games` 表（JSON 序列化），与 genre/developer 等同理。
- 编辑入口：管理端游戏编辑弹窗新增"存档路径"编辑器（最多 3 条，可增删，含通配符路径）。

### 2.2 备份记录（可选，本地索引）

```ts
// 某游戏在某时间的备份快照（存数据根/backups/index.json 或数据库新表）。
interface SaveBackupRecord {
  id: string;            // uuid
  gameId: string;
  gameName: string;
  userId?: string;       // 关联的登录用户（可选）
  createdAt: string;     // ISO 时间
  destPath: string;      // 备份文件实际存放路径
  provider: "local" | "usb" | "cloud";  // 存储接口
  fileCount: number;
  totalBytes: number;
}
```

### 2.3 存储提供者抽象

```ts
interface StorageProvider {
  id: "local" | "usb" | "cloud";       // 提供者 id
  label: string;                        // 显示名（本地目录 / U盘 / 网盘 / 云盘）
  // 保存备份文件
  save(sourceFile: string, destPath: string): Promise<void>;
  // 读取备份文件
  load(sourcePath: string, destFile: string): Promise<void>;
  // 选择目标路径
  pickTarget(): Promise<string | null>;
}
```

## 三、备份流程

### 3.1 自动备份（游戏退出时）

```
游戏进程退出（process.ts onProcessExit 钩子）
        │
        ▼
1. 该游戏配置了 savePaths？ ──没有──▶ 跳过
        │ 有
        ▼
2. 解析 savePaths（resolvePath 展开 {游戏库名}，校验存在）
        │
        ▼
3. 收集这些路径的文件/目录，生成自解压 exe（NSIS）
   （内部结构：manifest.json + 文件/目录 + .nsi 编译产物）
        │
        ▼
4. 通过 StorageProvider 保存到"用户指定的备份目录"
   （可配置，默认：<数据根>/backups/）
        │
        ▼
5. 写入备份索引记录，提示成功（可静默/托盘提示）
```

### 3.2 手动备份

用户点击"备份存档"，流程同上，但由用户选择目标存储位置和文件名。

### 3.3 备份包内部结构

```
废品机械师-网吧联机版——游戏存档20260206200923.exe   # NSIS 自解压安装包（最终产物，默认放用户桌面）
废品机械师-网吧联机版——游戏存档20260206200923/      # 工作目录（生成后自动清理）
├── manifest.json     # 元信息：游戏名、时间、路径清单、版本
├── files/            # 实际文件/目录（按路径 id 组织）
│   ├── p0/           # 存档路径1 匹配到的内容
│   └── p1/           # 存档路径2 匹配到的内容
└── 备份脚本.nsi      # NSIS 脚本（makensis 编译成 exe）
```

- **命名**：`<游戏名>——游戏存档<YYYYMMDDHHmmss>.exe`（分隔符可自定义）。
- **默认位置**：用户桌面（`os.homedir()/Desktop`），可让用户选择其它位置。
- `manifest.json` 记录"每个路径备份的内容 + 恢复时要放回的位置"，恢复时据此展开。

### 备份包内部结构

备份包是一个**自包含的目录**（便于将来云端/网盘上传）：

```
巫师3存档-20260815-142530/
├── manifest.json     # 元信息：游戏名、时间、路径清单、版本
├── files/            # 实际文件/目录（按路径 id 组织）
│   ├── p0/
│   │   ├── settings.ini
│   │   └── ...
│   └── p1/
│       └── save.dat
└── 巫师3存档-20260815-142530.nsi  # 可选：NSIS 脚本（若启用打包 exe）
```

- **`manifest.json`** 记录了"每个路径备份的内容 + 恢复时要放回的位置"，恢复时据此展开。

## 四、NSIS 自解压方案（多路径）

> 需求核心：生成一个**可双击恢复**的独立 exe（如 `巫师3存档-当时时分秒.exe`），
> 双击后自动把多个路径放回正确位置。

### 4.1 为什么用 NSIS（对比 WinRAR）

| 维度 | WinRAR 自解压 | NSIS 安装包 |
| --- | --- | --- |
| 多路径 | 需手工制作脚本，复杂 | 原生支持多文件/多目录安装 |
| 恢复逻辑 | 只能解压到指定路径，不能自定义 | 可写脚本控制安装位置、覆盖策略 |
| 用户提示 | 简单 | 可自定义欢迎页/完成页/进度条 |
| 依赖 | 需安装 WinRAR | 免安装，NSIS 是免费开源编译器 |
| 可控性 | 低 | 高（可加备份前校验、路径映射） |

**结论**：NSIS 更适合"多路径备份-恢复"。

### 4.2 NSIS 脚本生成

程序动态生成 `.nsi` 脚本，用 NSIS 编译器（`makensis.exe`）编译成自解压 exe：

```nsi
; 巫师3存档-20260815-142530.nsi
Name "巫师3存档"
OutFile "巫师3存档-20260815-142530.exe"
InstallDir "$INSTDIR"

; 每个存档路径 → 安装段
Section "存档1"
  SetOutPath "$DOCUMENTS\The Witcher 3\gamesaves"
  File /r "files\p0\*.*"
SectionEnd

Section "存档2"
  SetOutPath "C:\def"
  File /r "files\p1\*.*"
SectionEnd
```

- 恢复目标路径从 `manifest.json` 读取，动态写入 `.nsi`。
- 用 `SetOutPath` 处理"不同盘符/不同目录"（多路径的核心能力）。
- 用户双击 exe → NSIS 默认安装到配置的各路径 → 完成。

### 4.3 NSIS 依赖

- 打包 exe 时需要本机装 NSIS（或内置 `makensis.exe`）。
- 若本机没有 NSIS，**降级方案**：备份为普通 zip（+ manifest），提示用户用"恢复"按钮手动恢复（仍可用）。

## 五、存储接口（StorageProvider）

系统抽象 `StorageProvider`，内置几个实现，未来可扩展：

| provider id | 说明 | 选路径方式 |
| --- | --- | --- |
| `local` | 本地目录 | 打开目录选择对话框 |
| `usb` | U盘/移动盘 | 打开目录选择（默认到可移动磁盘） |
| `cloud` | 网盘目录 | 打开目录选择（映射盘 / 网盘同步文件夹） |
| `plugin`（预留） | 第三方/云端 | 插件接口 |

- 每个 provider 实现 `save`/`load`/`pickTarget`。
- 客户端通过"登录用户"标记备份归属（`userId`），未来云端可做账号隔离。

---

## 六、用户登录联动

- 备份记录带 `userId`（当前登录用户）。
- 备份文件命名带用户名（可选）：`巫师3存档-用户名-时间.exe`。
- 恢复时校验：只能恢复当前登录用户的备份（或允许游客恢复任意——按管理端策略配置）。
- 与现有登录系统（`auth.ts`）对接：`CurrentUser` 提供 `id` / `account` / `name`。

## 九、实施依赖与风险

| 依赖/风险 | 说明 | 应对 |
| --- | --- | --- |
| **NSIS 编译器** | 生成自解压 exe 需要 `makensis.exe` | 管理端打包机预装 NSIS；客户端纯执行恢复不需要 NSIS（双击已编译好的 exe 即可） |
| **备份目录可写** | 自动备份要写 `backups/` | 启动时确保目录存在；失败降级提示 |
| **恢复权限** | 存档路径可能在 C 盘系统目录 | 恢复时可能需管理员权限（NSIS 可用 `RequestExecutionLevel admin`） |
| **多盘符路径** | 存档路径跨 C/X 盘 | NSIS `SetOutPath` 天然支持任意盘符/目录 |

## 十、恢复流程

```
用户选择备份 exe / 或点"恢复存档"选择备份文件
        │
        ▼
1. 读取 manifest.json（备份包里）
   （若选的是自解压 exe，双击 exe 由 NSIS 直接执行恢复，不需进应用）
        │
        ▼
2. 展示将恢复的路径清单 + 目标位置（可预览）
        │
        ▼
3. 备份目标位置的现有文件（可选，防覆盖丢失）
        │
        ▼
4. 展开 files/ 到各目标路径
        │
        ▼
5. 完成提示
```

> 恢复有两种入口：
> - **自解压 exe**：用户直接双击（适合在别的机器上手动恢复，不依赖 Playday）。
> - **应用内"恢复"**：从备份索引/浏览文件选择，Playday 内部展开（适合未登录游客或有 UI 需求时）。
