# 背景音乐（BGM）设计

> 需求原话：*"再添加背景音乐，文件夹可配置。现在暂时用 D:\KwDownload\song"*。

一句话：**配置一个音乐目录 → 进主界面自动随机循环播放 → 状态栏一键控制**。

## 一、已确认的决策（与用户逐条确认过）

| 维度 | 决策 | 为什么 |
| --- | --- | --- |
| 播放方式 | **三种循环模式可切**：随机（默认）/ 顺序 / 单曲 | 单曲循环 = 自动播完重放；随机 = 整张歌单洗一轮再重洗（网吧场景：不能每天都从同一首开头） |
| 控件位置 | **底部状态栏最右**（上一首/播放/下一首 + 曲名） | 不干扰主界面；和"网络信息 / 提示轮播"同一行 |
| 详细控件 | **点曲名弹出面板**：进度、音量、循环模式、曲目列表 | 状态栏只有 26px 高，硬塞会把状态栏挤成工具栏（见"六、面板"） |
| 自动播放 | **进入主界面就播** | 后台音乐的本意；音量可调、暂停一键 |
| 目录配置 | **设置界面可改 + config.json** | 设置 → 通用 → 背景音乐 → 音乐文件夹（路径输入 + 浏览…）。界面里**只显示文件名，不显示路径** |
| 音量 | 0~100，默认 50 | 设置面板与音乐面板两处都能调，拖动即时生效、320ms 防抖落盘 |
| 模式记忆 | 写进 `config.json`（`musicMode`） | 网吧场景：设成"顺序播放"后重启应当保持 |
| 放视频时 | **背景音乐自动暂停** | 内置播放器：关掉浮层后自动续放；系统播放器：只暂停（感知不到何时关，见"七"） |
| 启动游戏时 | **背景音乐自动暂停**（退出游戏**不**自动恢复） | 游戏多半全屏，主界面被挡住、用户找不到播放控件；而"游戏退出"事件不可靠，见"八" |

## 二、目录与文件

`settings.musicDir`（`config.json`）：

- **未配置** → `<数据根>/music`（与封面、详情页等数据目录的约定一致）；
- **绝对路径原样**；**相对路径以应用 exe 所在目录为基准**（与其它路径字段一致，见 `shared/pathConfig.ts`）；
- 扫描是**递归的**（最多 4 层，防有人把目录指到盘根），跳过 `.` 开头的隐藏项；
- 认的扩展名：`mp3 / flac / wav / m4a / aac / ogg / opus / wma`
  （Chromium 原生能解前 7 种；wma 一般放不出来，但列在表里 —— 播放失败会自动跳下一首，不会卡住）；
- **目录不存在 / 里面没有音频** → 视为没有背景音乐：前端**不渲染音乐控件**（状态栏保持干净）。

解析落点：`electron/core/paths.ts` 的 `musicDir()` → `electron/core/music.ts` 的 `musicDirInfo()`。

## 三、音频怎么送到播放器

**走本地 HTTP 服务器**（详情页用的那个，惰性启动）：

```
前端 <audio src> ← http://127.0.0.1:<随机端口>/music/<相对路径> ← electron/core/music.ts 校验并读文件
```

为什么不直接给 `file://` 路径（和自带字体同一个理由）：

- 开发态页面是 `http://localhost:5173`，Chromium **不允许 http 页面加载 file:// 子资源**；
- 打包态虽然是 `file://` 能用，但两态行为不一致以后更难查；
- HTTP 那条路由带 `Access-Control-Allow-Origin: *`（跨源必需）并支持 **Range** ——
  所以进度可以拖动，不必整首下完才开始播。

安全：`/music/*` 只放行音乐目录下的真实文件（拒绝 `..`、绝对路径、盘符、非音频扩展名），
见 `resolveMusicRequest()`；越界与不存在的请求一律 404。

## 四、播放逻辑（为什么拆成"纯逻辑 + store"）

| 文件 | 职责 |
| --- | --- |
| `shared/models.ts` | `musicDir` / `musicEnabled` / `musicVolume` / `musicMode` 设置字段 + `MusicMode` 类型（前后端共用） |
| `electron/core/music.ts` | 目录解析、递归扫描、请求校验（主进程，读写文件） |
| `electron/ipc/music.ts` | `get_music_library`：返回目录 + 曲目列表（每首带可播 URL） |
| `src/utils/musicQueue.ts` | **纯逻辑**：三种模式的排队规则、洗牌、下一首/上一首、切模式重排、队列有效性（可单测） |
| `src/utils/clock.ts` | 秒 → `m:ss` / `h:mm:ss`（音乐进度与详情页运行时长共用同一套进位规则） |
| `src/utils/__tests__/musicQueue.test.ts` | 单测：三种模式 ×（自动播完/手动下一首）× 切模式 × 空目录/单曲库 |
| `src/stores/musicStore.ts` | 模块级 `<audio>` + 状态（曲目/队列/模式/播放中/音量/进度），控件的"遥控对象" |
| `src/components/MusicPlayer.tsx` | 状态栏控件：上一首 / 播放暂停 / 下一首 + **可点的曲名**（开面板）；Esc/点外面关面板 |
| `src/components/MusicPanel.tsx` | 音乐面板：进度（可拖）/ 音量 / 三种循环模式 / 曲目列表（文件名，当前高亮，点即播） |
| `src/App.tsx` | 接线：换目录→重拉曲库；开关→播/停；音量→同步到 `<audio>`；模式→同步进 store（并校验非法值） |
| `src/App.tsx` + `src/components/StatusBar.tsx` | 状态栏挂在外壳层（不是某个页面）：主页与游戏详情页都能看到音乐控件 |

**为什么 `<audio>` 放模块级而不是 React 树里**：切视图、重渲染、开关设置面板都不该打断播放；
而且全应用只能有一个播放器（多个 `<audio>` 会同时出声，听起来像回声）。

**几处刻意的稳健性设计**：

1. 曲库变化（换目录、增删文件）会让队列**失效并重洗**，否则会指向已不存在的曲目 ——
   表现是"点下一首没声音"，属于最难查的一类问题；
2. 单首播放失败（格式不支持 / 文件被删）→ 自动跳下一首；但**连续 3 首失败就停下来**并打印日志，
   避免"整个目录都放不出来"时无限快速跳过；
3. 切换曲目时**不重设相同的 `src`**，否则每次重渲染都会从这首开头重放。

## 六、音乐面板（点曲名弹出）

状态栏只有 26px 高：塞得下"上一首/播放/下一首"，塞不下进度条 + 音量 + 模式 + 曲目列表。
所以分成两层 —— 状态栏放"一眼能用的"，其余进面板（`MusicPanel.tsx`）：

| 区域 | 内容 |
| --- | --- |
| 头部 | 当前曲名 + 所在子文件夹名（有才显示）+ 关闭按钮 |
| 进度 | 可拖滑杆 + `1:05 / 4:05`（走 `/music/*` 的 Range，拖到哪都能立刻播） |
| 模式 | 单曲循环 / 顺序循环 / 随机循环（当前模式高亮，点击即换并写回 `musicMode`） |
| 音量 | 滑杆 0~100，即时生效 + 320ms 防抖落盘（与设置面板里的做法一致） |
| 列表 | 曲目列表：**只显示文件名**（子目录名作为淡色小标签），当前曲高亮，点即播 |

**为什么不把面板做成 `absolute`**：外壳 `.app-shell` 是 `overflow: hidden`（防止页面内容把状态栏顶走），
绝对定位会被裁掉；面板用 `position: fixed` + `bottom: 32px; right: 10px`（贴着窗口右下、
位于状态栏上沿之上）。层级 `900`：盖得住页面内容与详情页 iframe，但低于遮罩弹窗（`.modal-overlay` 1000），
所以打开设置时不会被它压在下面。

**关闭方式**：Esc / 点面板外 / 再点一次曲名。这三件事都放在 `MusicPlayer` 里做
（只有它同时知道触发按钮和面板的位置），否则会出现"点按钮打开、同一击又被判成点外面关掉"。
点外面用 `pointerdown` 且监听延后一帧挂载，就是为了避开这一类自打架。

## 七、与视频的联动（放视频时音乐让位）

需求：**点播放视频默认暂停背景音乐**。

| 播放路径 | 开始播视频 | 视频暂停 / 放完 |
| --- | --- | --- |
| 详情页页面里的视频（服务器注入的区块，来自 `videos/` 目录） | 暂停音乐 | **自动续放**（前提：开始播之前音乐本来在放） |
| "用系统播放器打开"（mkv/flv/avi 这类） | 暂停音乐 | **不自动续放** —— 外部播放器何时关我们感知不到 |

怎么知道视频在播：详情页是**跨源 iframe**，父页面收不到它的 `<video>` 事件，
所以由**注入进页面的脚本**主动 `postMessage` 通知主界面
（`playday-video-play` / `playday-video-stop` / `playday-video-external`，
见 [游戏静态详情页](./game-details.md) 的"本地视频"一节）。

为什么外部播放器不自动恢复：唯一能感知的信号（窗口重新获得焦点）会把"Alt+Tab 回来拿个东西"
也当成"看完视频了"，音乐突然响起来比不恢复更烦人；宁可让用户自己点一下播放。

实现要点（`src/stores/musicStore.ts` 的 `duckForVideo` / `unduckAfterVideo`）：
两个模块级标记 —— `ducking`（有一次让位还没结束）与 `duckResume`（那次暂停前本来在放）。
- **只在第一次让位时记录** `duckResume`：否则在浮层里连点几个视频，第二次进来音乐已经停了，
  会误记成"本来没放"，关掉后就不恢复了；
- **用户手动操作即解除让位关系**：`play/pause/toggle` 会把 `duckResume` 清掉 ——
  用户自己接管过之后，关掉视频不该再擅自恢复。

> 边界：只有**我们注入的那段视频区块**会通知主界面。如果某个游戏的详情页 HTML 里
> **自己另外埋了播放器**（模板里的 DPlayer / `<video>` / 视频 iframe），那个我们收不到事件、
> 也就不会暂停音乐 —— 要联动的话得在它自己的模板里加一句
> `parent.postMessage({ type: "playday-video-play" })`。

## 八、启动游戏时也让位（只停，不自动恢复）

需求：**启动游戏的时候，也暂停播放背景音乐**。

落点是一句话：`src/stores/gamesStore.ts` 的 `launchGame()` 里，**真正启动前**调用
`useMusicStore.getState().pause()`。所有启动入口（网格卡片上的播放键、右键菜单"启动"、
资讯页、以及"多个启动项"选择弹窗）都走这一个函数，所以只接一处就够了 ——
弹窗那条也对：用户选定某一项后会带着 `actionId` 再调一次 `launchGame`，那时才真正启动、
也才暂停。

**为什么放在"真正启动前"、而不是函数开头**：`launchGame` 开头有两条提前返回 ——
"等级不够"（只弹个提示、什么都没启动）和"有多个启动项，先把选择窗推给用户"。这两条
都**没有真的启动游戏**，此时把音乐掐掉属于误伤（用户可能只是点开看看有哪些启动项，
转头还想接着听歌）。这条边界和"只停不恢复"都由
`src/stores/__tests__/gamesStore.test.ts` 的四个用例钉住。

**为什么"只停不恢复"**（不套用第七节那套"让位 → 关掉后续放"）：唯一现成的"游戏结束"
信号是主进程的 `game_exited`，而它只为"要不要问用户备份存档"服务 ——
`saveBackupMode` 是 `auto` / `never`、或该游戏没配存档路径时**根本不发**
（见 `electron/ipc/saveManager.ts`）。拿一个"随设置而变"的事件当恢复依据，表现就是
"有时续放、有时不续放"，比干脆不恢复更难理解。所以退出游戏后想接着听，状态栏点一下
播放键即可。

> 要做到"游戏退出就续放"且行为稳定，得让主进程在**每次**游戏进程退出时单独推一个事件
> （与存档备份无关的那条链路）。那是另一件事，这一版刻意不做。
