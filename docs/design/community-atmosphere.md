# 多人氛围营造（Community Atmosphere）设计

## 一、需求背景

当前 Playday 是**单人使用**的游戏库系统（个人登录或企业匹配 IP），界面没有"其他人也在用"的感知。用户希望**营造类似弹幕 / 论坛 / 直播的多人氛围**，让用户觉得"不是只有自己在用，而是一群人在玩"，提升陪伴感和社区感。

目标：在不破坏现有单机体验的前提下，给界面注入"热闹、活跃、有同伴"的感觉。

## 二、两种方案

| 方案 | 做法 | 优点 | 缺点 |
|------|------|------|------|
| **方案一：随机模拟** | 前端随机生成"在线用户 / 弹幕 / 活动流 / 互动数" | 零后端、零成本、立即可用、观感热闹 | 数据是假的，长期可能"看穿" |
| **方案二：真实互动** | 后端收集多用户真实行为，展示真实在线 / 评论 / 弹幕 | 真实、可持续、有真实社区价值 | 需要后端服务 + 一定用户量才有效果 |

## 三、建议架构：分层递进（模拟先行，真实可切换）

两种方案**不是二选一，而是递进关系**：

```
        ┌─────────────────────────────────────┐
        │  前端"社区氛围"层（presentation）      │
        │  在线用户/弹幕/活动流/互动数 的展示组件   │
        └──────────────┬──────────────────────┘
                       │ 通过统一的"数据源接口"取数
        ┌──────────────▼──────────────────────┐
        │  数据源适配层（provider）             │
        │  · mockProvider（方案一：随机模拟）    │
        │  · realProvider（方案二：真实后端）    │
        └─────────────────────────────────────┘
```

- **默认用 `mockProvider`**（方案一），前端随机模拟，做出热闹氛围，**零成本立即可用**。
- **预留 `realProvider` 接口**（方案二），以后接后端（WebSocket + 数据库）时**只换 provider**，前端展示组件不变。
- 可在设置里加"氛围来源：模拟 / 真实"开关（真实未接入时置灰）。

> 这样既快速见效，又为真实互动预留了清晰升级路径，避免"先做假的、以后没法接真的"。

## 四、方案一：随机模拟（mockProvider）

纯前端模拟，数据在本地生成、本地消费。所有"用户"是虚拟角色。

### 4.1 模拟元素

| 元素 | 说明 | 展示位置 |
|------|------|---------|
| **在线用户列表** | 虚拟头像 + 昵称 + 正在玩的游戏，数量随机波动（如 3~20 人） | 侧栏底部"谁在玩" |
| **弹幕 / 实时动态** | 顶部飘过虚拟评论（"这游戏超好玩！""通关了！"），随时间随机出现 | 主内容顶部弹幕层 |
| **活动流** | "xxx 刚刚开始玩《xx》""xxx 通关了《xx》""xxx 收藏了《xx》" | 侧栏/通知 |
| **互动数** | 虚拟的"在线/玩过/喜欢"计数（如"124 人在玩"） | 详情页、卡片角标 |

### 4.2 模拟规则

- **昵称库**：预设一组中文昵称 + 中性头像（不冒犯、无真实用户信息）。
- **随机弹幕文案库**：预设一批"通用评论"（正面、无剧透、不涉及具体隐私）。
- **时间驱动**：`setInterval`（如每 20~40 秒）随机产生一条动态/弹幕；在线人数在区间内随机浮动。
- **与真实状态混合**：模拟"正在玩"尽量贴合当前游戏库（如"有人正在玩热门游戏"），增强可信度。
- **不误导**：模拟数据**不进入数据库**，只在内存/前端展示；标注为"模拟氛围"（可隐藏）。

### 4.3 实现要点
- 纯前端 `useCommunityAtmosphere` hook + zustand store（内存态，不持久化）。
- 随机数用 `Math.random`；昵称/文案从预设数组取。
- 弹幕用 CSS 动画（横向飘过）或 framer-motion。
- 全部可一键隐藏（设置开关），避免打扰专注玩家。

## 五、方案二：真实互动（realProvider）

需要后端服务支持，收集多用户真实行为。**当前 Playday 是单机 Electron + 本地 SQLite**，真实互动需要**联网后端**。

### 5.1 需要的能力

| 能力 | 实现 |
|------|------|
| **真实在线** | 客户端连接后端 WebSocket 心跳，后端维护在线用户列表 |
| **弹幕/评论** | 客户端发评论 → 后端存数据库 → 广播给其他在线客户端 |
| **正在玩状态** | 游戏启动/退出时上报后端，广播"xx 正在玩 xx" |
| **点赞/收藏** | 共享计数存后端数据库 |

### 5.2 架构
```
客户端 A ──┐
客户端 B ──┼── WebSocket/HTTP ──► 后端服务 ──► 数据库
客户端 C ──┘                         │
                                    ▼
                            广播给所有在线客户端
```

### 5.3 与现有登录的结合
- 复用现有 `CurrentUser`（个人账号 / 企业用户），真实互动以登录用户身份发言。
- 未登录时降级为"游客"（或提示需登录才能参与互动）。

### 5.4 当前状态
Playday 尚无此后端服务。方案二属于**未来演进**，当前只**预留接口**（realProvider 空实现），暂不实现后端。

## 六、统一数据源接口（provider 抽象）

前端展示层不关心数据来源，只依赖统一接口：

```ts
// src/utils/community/provider.ts
export interface CommunityProvider {
  /** 当前在线用户列表（含昵称/正在玩） */
  getOnlineUsers(): Observable<OnlineUser[]>;
  /** 实时动态流（弹幕/活动） */
  getActivityStream(): Observable<CommunityActivity[]>;
  /** 某游戏的互动计数 */
  getGameStats(gameId: string): { online: number; played: number; liked: number };
  /** 发送一条弹幕/评论（真实时提交；模拟时本地回显） */
  sendMessage(text: string): Promise<void>;
}
```

- `mockProvider`：实现为随机模拟（方案一）。
- `realProvider`：预留空壳（方案二，待后端）。

```ts
// 当前用哪个 provider（设置里可切，真实未接入时固定 mock）
const provider: CommunityProvider = settings.communitySource === "real" ? realProvider : mockProvider;
```

## 七、数据模型（前端内存态）

```ts
interface OnlineUser {
  id: string;          // 虚拟或真实 uid
  nickname: string;
  avatarColor: string; // 头像底色（不存图片）
  playingGame?: string; // 正在玩的游戏名
}

interface CommunityActivity {
  id: string;
  type: "start" | "finish" | "like" | "comment" | "online";
  user: OnlineUser;
  game?: string;
  text?: string;
  at: number;          // 时间戳
}

interface GameCommunityStats {
  gameId: string;
  online: number;      // 正在玩
  played: number;      // 玩过
  liked: number;       // 喜欢
}
```

## 八、UI 展示位置

1. **侧栏底部"谁在玩"**：在线用户小列表（头像圆点 + 昵称 + 正在玩的游戏）。
2. **主内容顶部弹幕层**：可选，顶部飘过短评（默认半透明、可关闭）。
3. **活动流通知**：右下角 toast 弹出"xx 正在玩《xx》"（低频，不打扰）。
4. **详情页互动区**：显示"xx 人在玩 / 玩过 / 喜欢"计数 + 底部评论区（模拟时放虚拟评论）。
5. **设置开关**："社区氛围"开关 + "模拟/真实来源"（真实置灰）。

## 九、实现步骤（建议）

**阶段 1（方案一·模拟）**
1. `community` 目录：`provider.ts`（接口）+ `mockProvider.ts`（随机模拟）+ `store.ts`（zustand 内存态）。
2. UI 组件：`WhoIsOnline`（侧栏）、`DanmakuOverlay`（弹幕）、`ActivityToast`（活动流）。
3. 设置：`communityEnabled` / `communitySource`。
4. 详情页互动计数 + 模拟评论。

**阶段 2（方案二·真实，预留）**
5. `realProvider.ts` 空实现 + WebSocket 后端规划（不在本期实现）。
6. 接入真实登录用户身份。

## 十、风险与注意
- **不误导**：模拟数据要标注"模拟氛围"，可一键隐藏，避免用户误以为真实在线。
- **打扰控制**：弹幕/活动流**低频**，避免干扰浏览游戏库。
- **性能**：纯前端模拟无网络，开销极小。
- **隐私**：虚拟昵称不得使用真实用户名/敏感信息。
- **可切换**：mock → real 只换 provider，前端展示组件不改，升级路径清晰。
